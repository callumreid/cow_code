# Native Codex runtime experiment

CowCode has an isolated, opt-in stdio adapter prototype for the locally installed Codex app-server. It does not change the default runtime, accounts, model selection, existing conversations, or the desktop application. Importing the adapter has no side effects; the caller owns its separate native process and must close it.

From `packages/opencode`, with `codex` and `bun` on `PATH`:

```sh
bun script/codex-app-server-smoke.ts --run
```

The explicit `--run` flag uses the existing Codex account for two small model turns. The script creates a temporary workspace and its own native thread, reads a known fixture, restarts its app-server process, resumes that same thread, steers a harmless `sleep 45` turn, interrupts it, and archives its test thread. It removes the temporary workspace and prints a compact evidence report. It never lists existing threads or changes authentication. A failed cleanup is visible as `archived: false`; the report retains the test thread ID so it can be cleaned up explicitly.

The adapter supports native model discovery, thread start/resume, streamed notifications, turn start, steer, interrupt, and archive. Register notification listeners before starting a turn: an immediate completion can arrive before the request response. A steer also requires an active native turn; the smoke waits for a command item to start before steering. A timed-out mutation has uncertain execution state and is never automatically retried.

Command and file-change approvals are individual callbacks with an abort signal. Without a callback, on callback failure, or after the deadline, the adapter declines. It does not grant persistent approvals or policy amendments. Other server requests return an unsupported-method error. This is transport groundwork, not a finished CowCode approval UI or production runtime switch.

Protocol shapes were checked against TypeScript generated by the installed Codex **0.144.6**, using `codex app-server generate-ts --out <directory>`, and the [official app-server documentation](https://learn.chatgpt.com/docs/app-server). The adapter validates the small response subset it consumes and preserves notification payloads for a future UI mapping; it does not vendor an entire generated protocol or pretend that a future Codex version is guaranteed compatible.

Validation on October 19, 2026 used native `gpt-5.6-sol`: streamed the correct fixture result (42), resumed one retained turn after restarting the process, accepted a steer, reported `interrupted`, and archived the test thread. Nine subprocess transport tests cover split frames, concurrent request IDs, early notifications, approval accept/decline/cancel/default-deny, approval deadlines, process exit, malformed output, and request timeouts. Approval roundtrips are fixture-tested; a live approval surface has not been validated. Native browser/computer tools, skills parity, spend reconciliation, restart recovery during an active tool, and end-user UI integration remain outside this bounded experiment.
